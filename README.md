## 当前页面

顶部「看板分析｜基础数据」为两个同级模块，当前模块高亮。看板分析左侧为存销看板、数据输入、采购到货核对、采购与调拨维护；基础数据左侧为物料、供应商、仓库、调拨路线、物料管控表、仓库映射。基础资料分类支持链接定位、刷新及浏览器后退；窄屏下菜单横向滚动，原有维护和导入功能保留。

- `http://127.0.0.1:8000/`：独立存销看板，保留组合筛选及分页。
- `http://127.0.0.1:8000/data-import`：独立数据输入、日期校验、数据质检和批次记录。
- `http://127.0.0.1:8000/master-data`：物料、供应商、仓库、调拨路线、物料管控表及仓库映射；从顶部「基础数据」模块进入。
- `http://127.0.0.1:8000/purchase-reconciliation`：金蝶与 FLUX 采购到货核对。
- `http://127.0.0.1:8000/data-edit`：采购信息和调拨物料信息维护。

如需 PostgreSQL 累计存储，在启动前设置 `POSTGRES_DSN`。未设置时系统保持本地可运行，不影响页面和自动化测试。

## 大数据量加载

采购到货核对页已补充单据关键词、供应商、仓库、物料文字查询（部分匹配，多个条件取交集）、回车查询、清空筛选及每页100条分页。存销看板的7个维度筛选支持直接输入片段查询，也可从候选项选择精确值；清空表示不限制。候选项每个输入框最多显示50项，输入文字后动态缩小范围。页面及静态资源要求缓存重新验证，避免项目更新后沿用旧界面。

存销看板、基础资料及仓库映射均按服务端分页加载，界面每页100行。存销看板复用同一业务日期的汇总，数据写入后缓存失效；翻页不重复传输未变化的筛选项。看板表头固定，表格内部滚动。

现有本地数据（271128个仓库×物料组合）的接口实测：首次加载约2.9秒，缓存后翻页约7–12毫秒；这不是浏览器整体渲染时间，也不代表所有电脑的性能。首次加载或修改数据后的重新汇总仍需要等待。验证详情见 [页面拆分与性能验证](reports/workspace-performance-20260917.md)。

## 当前计算口径

```text
可用库存 = 库存数量 - 分配数量 - 冻结数量

T+1预计库存 = 可用库存
             + T+1计划采购到货
             + T+1调拨入
             - T+1报货需求
             - T+1调拨出

T+2预计库存 = T+1预计库存
             + T+2计划采购到货
             + T+2调拨入
             - T+2报货需求
             - T+2调拨出
```

风险等级：

- 红色：T+1 或 T+2 预计库存小于 0。
- 黄色：没有缺货，但预计库存低于安全库存。
- 绿色：T+1/T+2 预计库存均高于安全库存。
- 默认安全库存为 T+1、T+2 平均需求的 1 天，可在页面修改安全库存天数。

> 注意：第一版把有效采购订单的剩余入库量视为“计划采购到货”，尚未结合供应商发货、ASN、到仓待入库等履约状态。下一阶段接入采购异常后，再升级为“可信采购到货量”。

## Windows 一键启动

1. 解压项目。
2. 确保电脑安装 Python 3.11 或更高版本，安装时勾选 `Add Python to PATH`。
3. 双击 `start.bat`。首次运行会自动安装依赖，时间稍长。
4. 服务就绪后会自动打开 <http://127.0.0.1:8000>。请勿直接双击 `app/static/index.html`，否则接口和静态资源无法按服务路径加载。
5. 关闭命令窗口即可停止系统。

页面更新采用统一的内容版本号：所有站内菜单、右上角基础资料入口和脚本/样式资源都由服务端自动添加版本，避免从其他页面返回时命中旧地址缓存。HTML响应禁止存储；浏览器后退恢复页面时会检查版本，仅当版本已更新才重新载入，不清除相同版本的表单状态。已打开的旧版标签页需重新进入一次当前页面，之后正常使用菜单即可。

也可以在命令行启动：

```powershell
py -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload
```

## 正式数据最低要求

计算必须有：

- 库存余量：仓库、物料编码、库存数量。
- 报货订单实时：发货仓库、物料编码、送货日期、下单数量或计划发货数量。

建议同时上传：

- 采购订单：仓库、物料编码、交货日期、剩余入库数量。
- transfer：调出仓、调入仓、物料编码、调拨数量、预计送达时间。

入库日报和物料存销报表在本阶段完成识别与留档，后续用于采购履约核对和需求分析，暂不直接改变 T+1/T+2 风险数量。

已用真实导出字段验证的兼容项包括：`调出点/调入点`、`仓库名称(维表)`、`产品编码/产品名称`，以及合并台账中的“库存”工作表。

当前会把仓库名称末尾的 `DC`、`RDC`、`仓`、`仓库` 统一为“仓库”口径（例如“湖州DC”和“湖州仓库”统一为“湖州仓库”）。这只处理稳定的后缀差异；跨系统特殊别名仍应在下一阶段由仓库映射主数据维护。

## 数据日期与结果类型

- 优先从 Excel 日期字段识别业务日期和库存快照日期。
- Excel 中没有可用日期字段时，才从文件名中的 `YYYYMMDD` 回退识别。
- 库存日期等于基准日：允许生成正式结果。
- 库存滞后1天：允许生成正式结果，但质检报告显示警告。
- 库存滞后超过1天、晚于基准日或无法识别：禁止生成正式结果。
- 用户勾选“强制计算”后可以继续，但批次、页面和导出文件均标记为“模拟结果”。

## 仓库映射维护

顶部“基础数据”模块左侧的“仓库映射”支持新增、编辑和停用，也可以下载 Excel 模板后批量导入。可直接访问 `/master-data#mapping`。映射字段包括来源系统、原始仓库编码/名称、标准仓库编码/名称、特殊别名、启用状态、有效期和备注。

系统不会把自动标准化建议写入 `warehouse_mapping`。未命中正式映射的仓库会进入 `unmatched_warehouse`，等待人工确认后再维护为正式映射。

## 数据质检口径

质检报告记录工作表、原始/有效/删除行数、必填缺失、日期/数值解析失败、整行重复、未匹配仓库/物料、负数异常、文件日期状态和是否允许继续计算。重复数据只按整行完全相同判断，避免误删不同批次或不同订单。
